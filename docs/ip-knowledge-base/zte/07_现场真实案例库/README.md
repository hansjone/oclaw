# 07 现场真实案例库（私有）

> **定位**：存放**本项目/本客户现场**真实故障与处置记录（PPT/PDF 报告提炼、值班闭环沉淀等）。  
> **属性**：私有经验，可含现场拓扑指称、客户侧约定、内部编号；**不是**通用教材。

## 与 01–06 的关系

| 层级 | 内容性质 | 用途 |
|------|----------|------|
| `01`–`06` | **总结后的通用/可复用网络知识**（逻辑树、产品特性、基线、教材化案例模式、阈值、SOP） | 给排障「怎么想、怎么配、敲什么」 |
| **`07`（本目录）** | **现场私有真实案例**（一事一记，可追溯源报告） | 给「我们现场是否遇到过、当时怎么查的」 |

从 `07` 提炼出的稳定规律，应再写入 `01`/`02`/`03`/`06`（或写入 `04` 的教材化案例）；**不要**把未脱敏的客户细节写进 01–06。

`04_历史故障案例库`：保留**已总结、可公开给专家推理复用**的案例骨架（少客户私有信息）。  
新的现场报告与值班沉淀，**优先写入本目录 `07`**。

## 建议子目录

按协议/主题分，勿按「第几份 PPT」分：

```text
07_现场真实案例库/
├── README.md                 # 本说明
├── _TEMPLATE.md              # 入库模板
├── BGP/
├── OSPF/
├── MPLS_LDP/
├── 光与传输/
└── _staging/                 # 可选：模型草稿，未过审勿当正式知识引用
```

## 入库约定

1. 一案一文件 Markdown；文件名：`协议_现象关键词_YYYYMMDD.md`
2. 必填：现象、排查步骤、根因、修复、关键词、**源报告路径/页码**
3. 敏感信息：客户全名、公网 IP、账号口令等按需脱敏；保留排障所需的网元角色与命令输出
4. 状态：`draft`（未过审）/ `reviewed`（可被 playbook 正式引用）
5. 原 PPT/PDF 建议放 `_raw/` 或不进 git 的对象存储，md 内只留相对路径索引

## 检索提示（给 ops）

- 「以前现场有没有类似的」→ 优先 `search_files` 本目录 `07_现场真实案例库`
- 「标准怎么查/怎么配」→ 仍用 `01`–`06`
- 命中 `07` 后仍须用 netx 在**当前**网元验证，不得直接套用历史配置
